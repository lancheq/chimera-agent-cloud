# v2首次部署失效取证与数据矛盾状态核查

2026-11-15。结论：**11月14日16:06启动的批次已结束，但实际导入v1模块，不构成有效v2验证；数据矛盾尚未全部裁定，也没有实施按GT清洗。** 本报告记录明确的部署失败和只读数据审查，不将失效批次计作提分结果。

## 运行结果为何无效

该批次11月14日18:13:02结束全部尝试，18:14:32结束指纹检查并在私有分析阶段报错。两分片共182组别均终止、无pending，实际模型请求／返回760次，生成168份结构化预测。它们全部保留，不能因“输出了JSON”就宣称v2已验证。

部署时更换了入口和声明源码路径，却遗漏修改从v1复制的`environment.cwd`和`environment.PYTHONPATH`。因此入口虽然来自v2，Python导入的`shared_plan.py`等模块实际来自v1。元数据记录`control_interface_version=2`不足以证明v2代码执行。

| 取证项目 | 事实 |
|---|---|
| 声明的共享控制代码SHA | `71d153d146856b09c18a8dfa6d5c4ce67d38b9fad4eae01b464d628fdf6ffeff`，对应已接受v2 |
| 初始计划实际绑定的代码SHA | `ad399d1cc9b2e2a92a4829f99b9dab0f8ce280df568589ccfbcec6755d303585`，对应v1 |
| 控制请求是否附带新Schema | 760次请求中，response_format请求0次 |
| 实际绑定是否含control_schema.py | 无 |
| 私有分析 | `Output runtime source differs from protocol`，拒绝评分 |

这是执行会话的部署遗漏。原先静态verify只证明声明的文件、模型和资源未漂移，不能替代实际导入路径检查。11月14日的工程验收本身使用了正确v2代码；失效的是之后正式部署所继承的运行环境，不能用它来判断修复有效或无效。

原失效协议、配置、输出、日志和分析报错不改写。取证及3182份原始产物指纹位于`output/s4_v2_recovery_20261115/`。本次核查调用模型0次，不重新计算该失效批次的临床准确率。

## 补上的部署门槛

新增`tools/verify_shared_plan_runtime.py`，12项相关回归通过（7项实际环境／导入／入口保护，5项既有入口控制）。门槛包括：

- 工作目录、完整PYTHONPATH与声明快照一致；
- 已加载项目模块的实际`__file__`及字节SHA与冻结清单一致；
- 使用实际导入的RecordedModel／PolicyPlan做合成接口检查，确认Schema确实附到请求、空剩余计划表示停止，真实模型调用0；
- 每个worker在同一个Python进程完成检查后，才运行固定入口，降低“预检查对、正式进程错”的风险；
- 启动前完整verify、dry-run以及结束后的输出绑定核验继续保留。

实际负例已确认：旧环境在生成前被拒绝；修正环境的两个worker实际模块检查通过。沿用原已接受的278份v2源码、91例、顺序、种子、模型、知识库和信息预算，另建v2-r1部署恢复协议，不修改科学候选、不拼接旧失败例。恢复属于完成原已授权的v2完整对照，不开展新机制。正式启动信息另见当前状态。

## 数据矛盾解决了吗

**没有全部解决。** 现有P3只读复核覆盖三来源T1旧候选，不是完整T1/T2/T3一致性认证：

| 旧筛查171条标记 | 数量 |
|---|---:|
| PSA density误识别为血清PSA | 99 |
| 5%边界精度误报 | 3 |
| 明确历史／当前时点差异 | 3 |
| 算术残差，测量／精度未对齐 | 58 |
| PSA来源／时点未对齐 | 4 |
| 卡片／MRI密度来源差异 | 2 |
| 活检史结构化／文本不一致候选 | 2 |

105条筛查标记已解释，66条仍未裁定，涉及29保守风险组；标记不是独立患者数或已证实医学错误数。原值未替换、未生成清洗版输入，也没有把离线审计中看到的隐藏信息免费提供给agent。v2修复的是控制输出可靠性，不是临床信息矛盾解析器。

本次另按**来源版本＋任务＋病例匹配，并核对182份前置输入／临床文件SHA**，将P3审计映射到已预先选择的91例：

- 12例旧标记已解释；
- 79例未被旧筛查标记；
- 旧台账中未裁定标记在本91例中为0。

因此，不能把全数据池的66条标记误说成这91例有66处错误，也不能从0推断91例没有矛盾。样本按参考文件存在性预先选定，不按冲突标记剔除；这项映射没有改运行输入或参考答案。机器摘要在`output/s4_v2_recovery_20261115/data_conflict_scope.json`，原始审查见[来源／时点／量纲复核](ROUND2_CONFLICT_SOURCE_REVIEW_20261113.md)。

## 对所附评审意见的范围判断

附件对冲突数量和来源的解释，与本地审计一致；“尚未全面裁定”“不按GT选一组数值”仍成立。当前Fixed／Adaptive Shared Plan对照检验共同规划之后的修订权限，不能据此宣称优于官方Direct ReAct。附件的三组比较是后续候选建议，尚未执行，不能代替先完成本轮有效v2对照。也没有证明动态取证已识别或解决了这些冲突。

下一步先完成修正部署的有效v2配对及分析；数据侧继续保留来源、量纲与采样时点的不确定性，后续若设计冲突处理机制，必须只使用agent已合法取得的证据，单独登记和验证，不能将离线质量标记当免费特征或依GT修值。
