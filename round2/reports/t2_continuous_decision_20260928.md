# T2「连续值决策规则」实测报告（2026-09-28）

> 问题：能否把标签机制改成 0–1 连续值，以便调整输出、解决偏置、便于裁决？
> 本文按**官方目标函数**（不是准确率）做了配对重复 CV 实测。

---

## 0. 结论速览

| 项 | 结论 |
|---|---|
| predictor 的概率 | **本来就有**（4 类概率算完就扔，未传出去）——无需"改造"，只需"别再丢" |
| T2 决策门 | **不是 0/1**：一致 1.0 / **AS↔CS 混淆 0.5** / 其他 0.0 → 理论上 `argmax` 非最优 |
| **实测：期望最大化规则** | **不赚**。Δranking **−0.0071**（在噪声量级） |
| **实测：激进利用"半对"** | **大幅变差** Δranking **−0.1621**（macro-F1 0.652→0.376 崩掉） |
| 判定 | **"用连续值调决策"这条路在 T2 上被实测否掉**——与"标签级裁决器增益恒为 0"同类结论 |

## 1. 前提核实（改变了问题性质）

### 1.1 predictor 侧：概率一直都有

[predictor.py L810-L818]：

```python
proba_arr = m["clf"].predict_proba(X)[0]
proba = {k: float(v) for k, v in zip(names, proba_arr.tolist())}
label = names[int(proba_arr.argmax())]
return { ..., "probabilities": proba, "at_threshold": ... }
```

但全树搜索：**`"probabilities"` 在 `src/` 中只出现在这一行**——没有任何消费者。
`_predictor_note` 只渲染 `decision`（一个标签），trace 也从不写 `predictor_decision`。

→ **概率是"算完就扔"**。这也解释了 τ 机制为何曾经有效：它就是直接在 `proba["active_treatment"]` 上做阈值。

### 1.2 ★ T2 决策门是 1.0 / 0.5 / 0.0（不是 0/1）

`evaluate.py::decision_score`（L454-468）：

```
完全一致            → 1.0
AS ↔ CS 混淆        → 0.5     ← partial credit
其他错误            → 0.0
```
且 `case_score = 成分分 × 决策门`；T2 ranking = `0.5×decision_macro_f1 + 0.5×mean_case_score`（聚合 L1403）。

→ **所以"取 argmax 标签"并非最优规则**：当 `p(AS)+0.5·p(CS) > p(AT)` 时，
输出 AS/CS 能拿到"半对"而避免"全错"。这正是"连续值"本可以赚的地方。

## 2. 实测（`tools/t2_rule_cv.py`）

**方法**：10 seed × 5 fold = 50 折；GT-only、无伪标、折内预处理、严格配对；
生产同款 RF（400 树 / md=4 / msl=3）；用同一批 OOF 概率评估 4 条规则；
**case_score 的成分分量逐例取自真实批次**（`test/output.night_t2_base`）并固定不变
——规则只改决策门，不改成分。

| 规则 | E[decision] | macro-F1 | case_score | Δcase | **ranking 代理** | **Δrank** | 正确/部分/错误 |
|---|---|---|---|---|---|---|---|
| **`argmax`（当前生产）** | **0.8611** | **0.6523** | **0.4521** | — | **0.5522** | — | 61 / 2 / 9 |
| `emax_official`（partial=0.5）★理论正确 | 0.8472 | 0.6437 | 0.4464 | −0.0057 | 0.5451 | **−0.0071** | 60 / 2 / 10 |
| `emax_p075` | 0.8472 | 0.6437 | 0.4464 | −0.0057 | 0.5451 | −0.0071 | 60 / 2 / 10 |
| `emax_p100`（不罚 AS↔CS 混淆） | 0.7639 | **0.3763** | 0.4039 | −0.0481 | 0.3901 | **−0.1621** | 48 / 14 / 10 |

**读法**：

1. **理论上正确的规则反而略差**（−0.0071）：E-max 只把 1 例"正确"变成"错误"，
   且**没有多拿到任何"半对"**。原因是"半对"要求 GT∈{AS,CS}，这本来就不可知。
2. **越激进地利用"半对"，崩得越狠**（p100：14 例落到半对，但 macro-F1 从 0.652 → 0.376）。
   → 官方目标函数**自带反向惩罚**：堆叠 AS/CS 会把 macro-F1 打崩，净效果 −0.16。
3. 结论：**"用连续值去调决策"没有可用的余量**。这与之前"标签级裁决器增益恒为 0"
   是同一类结论——只是这次连"用概率做最优决策"都试过了。

---

## 3. 为什么会这样（机制层面的解释）

| 原因 | 说明 |
|---|---|
| 排序信息不足 | E-max 与 argmax 只在极少数例上不同；那些差异是噪声，不是信号 |
| 目标函数反向惩罚 | T2 ranking 含 macro-F1，堆 AS/CS 换"半对"会被 F1 反噬 |
| 项目已有两次同向证据 | ① τ=0.30 是"为 LR 概率尺度校准"的阈值，换 RF 后变成负贡献，已关闭（P1.4b）；② attribution §7.3 原话："**用规则/特征工程真正提升，而非调阈值**" |
| gate 归零的折扣 | 分数校准只有在能**翻决策**时才有价值；否则只是把数字调好看 |

---

## 4. 那么"连续值"该用在哪（保留它的真正价值）

调决策不赚 ≠ 概率没用。它的价值在**可测量性**，不在调优：

| 用法 | 价值 | 风险 |
|---|---|---|
| **传概率**（predictor → 证据表/trace） | 零决策影响；让裁决层与诊断有原料；补上"标签级裁决器增益=0"的前提 | 无 |
| **算 AUROC / 校准曲线** | 判断偏置是"档位错位"（阈值可修）还是"排序错误"（不可修）——**这才是有决定性的诊断** | 无 |
| 引入阈值调优 | — | ⚠️ 又一个未消融的可调参数（下一个 τ）；在本地 72/91 例上调 = 重演乐观数字 |

---

## 5. ★ LLM 侧若要加连续值的三个前置事实

| 事实 | 后果 |
|---|---|
| `Task1Judgment` / `Task2Judgment` 是 `extra="ignore"` | **只改 prompt 让 LLM 多输出概率字段 → 会被静默丢弃**，正是我们一直在找的"输出悬空" |
| LLM 自报信心质量差 | 项目实测 confidence 与 GT 匹配仅 **54–60%**；confidence 分 0.900 但 kappa=0 |
| 多采样频率是陷阱 | 系统性偏置下（AT 预测 46 vs 真实 31）多采样只会**把偏置量化成一个稳定的错数** |

→ 若真要 LLM 连续值，**第一步必须先在 Judgment 模型里加字段**（否则白做），
且必须先算 AUROC 判断值不值得。

## 8. ★ 追加：裁决网络（stacking）前置条件检验 —— 同样被否

> 用户设想：训练一个**网络或 LLM**，输入「LLM 连续值 + predictor 连续值 + 其他数据」，输出最终标签。
> 这是标准 stacking，方法本身正当。但它的收益上限完全取决于一件事：
> **特征里是否存在关于「predictor 何时会错」的可学信号。** 本节把这个前提测了。

### 8.1 信号强度（n=72，50 折 OOF 概率）

| 判据 | AUROC | 读法 |
|---|---|---|
| `margin`（p_max − p_2nd）→ 是否正确 | **0.6021** | 几乎随机（0.5 为随机） |
| 归一化熵(−) → 是否正确 | **0.5902** | 同上 |
| margin 在【错】例均值 vs【对】例均值 | 0.4563 vs 0.5356 | 差距极小 |

→ **信号存在但极弱**。在 72 例、11 例错误上，这个量级的 AUROC 支撑不起任何学习器。

### 8.2 诚实配对评估（10×5=50 折；**阈值与模型均在训练折内选**）

| 规则 | E[dec] | macro-F1 | rank 代理 | **Δrank** | **Δ/SE** | 胜/负 |
|---|---|---|---|---|---|---|
| **R0 `argmax`（当前生产）** | **0.8618** | **0.7795** | **0.6160** | — | — | — |
| R1 margin 门控 → 次优类 | 0.8478 | 0.7690 | 0.6078 | −0.0081 | **−3.48** | 0/10 |
| R2 margin + LLM 分歧 → LLM 标签 | 0.8071 | 0.7266 | 0.5765 | −0.0395 | **−6.89** | 0/28 |
| **R3 逻辑回归 meta（真正的学习器）** | 0.7851 | 0.6421 | 0.5262 | **−0.0897** | **−8.32** | **4/41** |
| （oracle，不可达上界） | 0.9028 | 0.8403 | 0.6555 | +0.0395 | — | — |

**R3 就是"训练出来的裁决器"的最小版本（4 类 × 6 特征），结果是全场最差：
Δrank = −0.0897、Δ/SE = −8.32、45 折里输 41 折。** 这是显著负收益，不是噪声。

### 8.3 为什么会这样（三条，缺一不可）

1. **融合器只能重新加权已有信息，不能创造信息。**
   现有输入里：predictor 的概率是**它自己的输出**（自信息）；LLM 的标签在分歧处准确率仅
   **~10.7%（基线）/ ~18%（Arm A）**——那是**负价值**的输入。所以无论换什么融合器
   （LR / 网络 / LLM），上限都被"输入里有没有新信息"锁死。R2（用 LLM 标签）比 R1 更差，
   正是这条的直接证据。
2. **样本量根本不够。** n=72、predictor 只错 **11 例**、LLM 分歧 27 例。
   参数最多的 R3 过拟合最重 → 实测也确实最差。这正是项目铁律"在本地 72 例上调参
   = 重演乐观数字"的又一次现身。
3. **oracle 的 +0.0395 是真的，但它是"信息上界"，不是"融合器上界"。**
   要吃到它必须靠**predictor 与 LLM 都没用的信息**（规则命中、指南阈值、PSA 动力学、
   病理量化原值），而不是靠更聪明的加权。

### 8.4 若要继续，唯一有意义的方向是**换输入**，不是换融合器

| 方向 | 判断 |
|---|---|
| 训练网络/LLM 做融合（现有特征） | ❌ 已实测负收益（−0.0897，Δ/SE −8.32） |
| 给融合器加**新信息**（规则引擎命中、指南阈值…） | ✅ 唯一可能吃到 oracle 的路径 |
| 传概率 + AUROC 诊断 | ✅ 零风险，仍值得做（可测量性） |
| T1 上做同样的裁决实验 | ⚠️ 唯一"两侧打平"（0.681 vs 0.692）的地方，**但同样必须先测信号**，且 n=91 仍很小 |

> 注：`P8 §2.6` 曾发现"显式临床规则层——精度完美但当前冗余"。若要做"用新证据纠错"的裁决层，
> 应当先让那个规则层**有覆盖**（它现在冗余是因为覆盖太低），而不是先建融合器。
