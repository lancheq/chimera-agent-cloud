## 复现与接线

修复前在原源码上重放 T1。一次实验室工具成功入账，B 已生成未裁注记。LangChain 将工具结果保为列表，SDK 在 `request_meter._validate_messages` 的内容检查处拒绝。第一条 agent 请求已到 MockTransport，工具后的第二条请求在合成计数前被拒绝，无两个输出文件。成功结果在 MCP 为一个 `TextContent`，业务正文与 `structuredContent.result` 精确一致。已装适配器把文本和嵌入文本资源映射成相似的 LangChain 形状，正常文本块另有本地生成的 `lc_` ID，因此仅凭 LangChain 文本外形无法确定原生类型。

本轮在代码注入的 B 合成会话中接线。运行器只为该会话安装 MCP 原生回执检查。它核对真实的服务器、工具、参数、运行时 call ID 和原生单文本形状，原返回继续走现有适配器和权限账本。B 复用同一次 ToolNode 的新结算回执，要求病例、会话、工具、字段和结果摘要一致。只有原生形状、临床可见性、唯一结算回执和派生 ToolMessage 全部匹配，agent 入口才复制消息并把内容从单块列表投影为原字符串。原始 graph 消息与其工具工件保留，调用 ID、顺序和文本字节均保持。SDK、权限合同、填表、最终字段和默认配置原样运行。代码变更限于 B 模块、runner 的合成客户端接线、agent 请求视图及对应测试。

私有回执保有原生结果及其摘要、原始 LangChain 块、结算请求 ID 和响应摘要、投影后的文本摘要。计数输入、SDK 提交、HTTP 校验和 MockTransport 消费以同一次请求绑定。正式填表仍看原 graph 消息。
