## 1. 为什么 T1 才是该测的地方

| 任务 | 谁在决策 | 两侧水平 | 裁决层前提 |
|---|---|---|---|
| T2 | **predictor override**（LLM 被覆盖） | 0.86 vs 0.61，悬殊 | ❌ 无（已否决） |
| **T1** | **LLM 自己**（无 override） | **0.670 vs 0.692，打平** | ✅ 有 |

## 2. ★ 而且 T1 上的"融合"**已经存在，只是隐式且不可观测**

`_predictor_note` 在 T1 同样把 predictor 的决策注入了 LLM prompt：

- `run.py:313-315`：只要 `predictor_task1` 已加载就设置 `predictor_decision`（**与 task 无关**）
- `_predictor_note`（`form_fill.py:413+`）对 task 1 渲染 `yes` → `"biopsy"` / `no` → `"no biopsy"`
- **T1 没有 override** → 这个提示**直接影响最终决策**

**实测证据**：P9 Arm C 关掉该提示后，**T1 决策翻转 7/91 例**。

→ 所以 T1 现状不是"单 LLM 主导"，而是
「**LLM 主导 + 一个隐式、不进 trace、不可测、不可调的 predictor 提示**」。
把它显式化 + 可测 + 可调，正是"决策层"设计的价值所在。**这一点用户是对的。**

## 3. 实测（10 seed × 5 fold = 50 折，配对）

**口径对齐生产**：T1 生产 bundle 是 **LR**，且 `num_names` 含 **5 个 kNN 特征**
（`knn_avg_outcome/avg_sim/avg_psa/avg_pirads/max_sim`）→ 必须打开 `TP._KNN` 并按折内索引重建，
否则预测器比生产弱（0.6593 vs 0.6703）。
成分分逐例取自真实批次（CTA 修正后的 tool 口径），规则只改决策门。

| 规则 | E[gate] | macro-F1 | **rank 代理** | **Δrank** | **Δ/SE** | 胜/负 |
|---|---|---|---|---|---|---|
| **R0 LLM 现行输出（当前生产，note ON）** | 0.6927 | 0.5823 | 0.5175 | — | — | — |
| R1 永远取 predictor（LR） | 0.6698 | 0.6423 | 0.5422 | +0.0247 | +1.36 | 30/20 |
| **R2 margin 门控 → 低 margin 改用 predictor** | 0.6220 | 0.5496 | 0.4812 | **−0.0362** | **−3.05** | 16/25 |
| **R3 逻辑回归 meta（真正的决策层）** | 0.6968 | **0.6887** | **0.5703** | **+0.0528** | **+3.31** | **35/15** |
| （oracle，不可达上界） | 0.8901 | 0.8777 | 0.7267 | +0.2092 | — | — |

**方法学要点**：R2 的阈值与 R3 的模型**都只在训练折内选择**（避免选择偏差）；
R0/R1 无参数。R3 特征 = `[p_no, p_yes, margin, LLM 决策]`，4 特征 2 类 → 参数量可控。

## 4. ★ 但机制是"修正锚定"，不是"融合独立信息"

把 LLM 换成 **Arm C（note OFF，无锚定）** 的决策重跑：

| LLM 口径 | R0（LLM 独立） | R3（决策层） | Δrank | **Δ/SE** | 胜/负 |
|---|---|---|---|---|---|
| **note ON（现行生产）** | 0.5175 | **0.5703** | **+0.0528** | **+3.31** | 35/15 |
| note OFF（Arm C 无锚定） | 0.5332 | 0.5471 | +0.0138 | **+0.94** | 25/25 |

**读法**：
- 去掉锚定后，LLM **自己就变好了**（0.5175 → 0.5332，E[gate] 0.6927 → 0.7035）
  → 锚定对 T1 **本身是轻微有害的**（与 P9 的"翻转 7 例、净 +1 不显著"一致，但方向上这里更差）。
- 而决策层的增益在无锚定时**消失**（+0.94，25/25 掷硬币）
  → **R3 的 +3.31 SE 主要来自"把锚定造成的问题修回来"，而不是"融合出新信息"。**
- 三个配置的最优仍是「锚定 + 显式决策层」（0.5703），说明锚定确实携带信息，
  只是以"不可观测"的形式藏着——**这正是应该把它显式化的理由**。

## 5. R2 的失败是重要警示

**朴素 margin 门控显著为负**（−3.05 / −4.23，胜率 16/25 与 11/30）。
即：**"让决策更可调"如果做成一个裸旋钮，比不加还糟。**
这与项目历史完全一致（τ=0.30 就是这样一个旋钮，最终被关闭）。

→ 结论：**可调整性必须有形式**——① 声明前置条件（机制注册表）；② 参数在训练折内选；
③ 有正对照；④ 进 trace 可观测。四条缺一就会变成"下一个 τ"。

## 6. 诚实的限制（必须随结论引用）

| 限制 | 影响 |
|---|---|
| **Δ/SE = +3.31 刚过 3 SE 门槛** | 是项目铁律②的**下限**，不是大余量 |
| **T1 本地 GT 是 `PT-pseudo_*` 伪标** | 本地↔平台迁移**未验证**；R3 在本地选参 → 存在"本地乐观"风险 |
| `rationale`（0.10）未评 | rank 代理只覆盖 0.90 权重 |
| oracle 为 +0.2092 | 说明 T1 上还远未到上限；有效余量存在但需要更多信息/更好融合 |

## 10. 实现与端到端 A/B（2026-09-28 执行）

### 10.1 生产系数（烘进 `resources/t1_decision_layer.json`）

| 项 | 值 |
|---|---|
| 特征 | `[p_no, p_yes, margin=\|p_yes−p_no\|, 1[LLM 决策=yes]]` |
| coef | `[−1.0595, +1.0595, +0.6705, +1.4501]` |
| intercept | `−1.6243` |
| 拟合 | 91 例 OOF 概率 + LLM 决策（LR `C=1.0, class_weight=balanced`，与离线 R3 同口径） |
| 工具 | `tools/fit_t1_decision_layer.py` |

**规则解读**：`logit = 1.06·(p_yes−p_no) + 0.67·|p_yes−p_no| + 1.45·1[llm=yes] − 1.62`
→ LLM 说 **no** 时基本维持 no（只有 predictor 接近极端置信才翻）；
LLM 说 **yes** 而 predictor 反对时会翻成 no。结果：yes 数 80 → **47**（GT 56）。

### 10.2 运行时实现（`form_fill.py`）

| 项 | 内容 |
|---|---|
| 开关 | `CHIMERA_T1_DECISION_LAYER=1` 启用（**默认 0 = 历史行为**） |
| 位置 | `_apply_decision_override` 之后、`_calibrate_weights` **之前**（使下游校准看到最终决策） |
| 备份 | `form_fill.py.bak_p10`、`.bak_p10b` |
| 补丁 | `tools/p10_add_t1_decision_layer.py`、`tools/p10_fix_layer_switch_order.py` |

**三条纪律（防重演历史失效模式）**：
1. **可观测**：无论是否改判，每次都写一条 `decision layer:` 开头的 warning 进 `trace.json`。
   （T1 的 `_predictor_note` 之所以危险，正因为它是"隐式、不进 trace、不可测"的融合。）
2. **失败不静默**：系数加载失败 → `LOAD FAILED … 未接通` + `log.error`；
   predictor 概率缺失 → `SKIPPED … 未接通`。绝不"悄悄不生效"。
3. **不动输出 schema**：只改 `judgment["biopsy_decision"]`，**不往 judgment 加新键**
   （`Task1Output` 是 `extra="forbid"`，加键会让产物校验失败——这正是本项目反复出现的坑）。

### 10.3 正对照（`tools/verify_t1_decision_layer.py`，**四项全过**）

| 概率缺失 → `SKIPPED` 警告 | ✓ |

附带数字：决策层相对 LLM **改判 33/91 例**，最终分布 `{no:44, yes:47}`。

### 10.4 端到端两臂（`scripts/run_p10_overnight.sh`）

| 臂 | 配置 | 输出目录 | 意义 |

### 10.5 判读（`tools/t1_ab_eval.py`）

输出：两臂的 决策准确 / macro-F1 / gate 期望 / case_score / **ranking 代理**，
决策翻转明细（救回 / 打坏），以及**决策层可观测性**（臂 2 中每例都必须带 `decision layer:` 记录）。

**接受的判据**（预注册）：
1. 臂 2 必须**每例**都有 `decision layer:` 记录（否则机制没接上 → 整臂作废）；
2. 两臂**成分分应基本不变**（决策层只改决策门）；若分量也变了 → 说明有意外耦合，需排查；
3. 主判据是 **ranking 代理的 Δ**，并给出翻转的救回/打坏计数。

**已知限制**（随结论引用）：predictor 在本地 91 例上是**样本内**预测（bundle 含这些例），
故臂间的决策层行为会比平台推理时更"自信"；且本地 GT 为 `PT-pseudo_*` 伪标，
**本地↔平台迁移仍未验证**。

### 11.2 三种口径的对比（同一批 91 例）

| 口径 | acc | macro-F1 | gate | case_score | **ranking** |
|---|---|---|---|---|---|
| **A 对照（LLM only）** | 0.6923 | 0.5804 | 0.6923 | 0.4521 | **0.5163** |
| **B 决策层（bundle 概率 ＝ 样本内）** | **0.8132** | **0.8087** | **0.8132** | 0.5294 | **0.6690** |
| **C 决策层（OOF 概率 ＝ 样本外）← 诚实** | 0.7143 | 0.7083 | **0.7143** | 0.4613 | **0.5848** |

| 比较 | Δrank | Δgate |
|---|---|---|
| **B vs A（端到端表面值）** | **+0.1528** | **+0.1209** |
| **C vs A（诚实口径）** | **+0.0686** | **+0.0220** |

**B 与 C 只差 11/91 例决策**，但这 11 例贡献了几乎全部差距（≈9 例）。

### 11.3 结论与教训

1. **端到端的 +0.1209 里，约 +0.099 是样本内乐观**：本地 `predictor_task1.joblib`
   就训在这 91 例上，它给出的概率过拟合，而决策层的输入正是这个概率 → 决策层"继承"了过拟合。
   **诚实值 ≈ gate +0.022 / rank +0.069**，与离线 CV 的 +3.31 SE **同向、同量级**。
2. **这是本项目头号故障模式（"本地数字乐观"）的又一次现身**，
   也正是本报告 §10.5 预注册限制里点名的那一条 —— **预注册的警告生效了，没有把 +0.15 写成成果**。
3. **决策层机制本身是接通的、可观测的**（91/91 触发、91/91 有记录、失败不静默），
   这一点已被端到端证实；**不确定的是它的真实幅度**。
4. 诚实幅度（净 +2 例 / n=91）**不足以宣称"确认有效"**——本地 GT 是伪标，且平台迁移未验证。
