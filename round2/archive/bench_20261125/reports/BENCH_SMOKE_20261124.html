官方 Baseline vs Adaptive v2 候选：N=6 冒烟对照

2026-11-24 · A 臂官方原件 1afa788 · C 臂 P01 生产候选 · 同一 GGUF、同一端点、同一评测器
三句话结论。 ① 两臂都能在真实病例上端到端跑通，输出合法、可被同一评测器打分、预算记账生效——对照装置成立。 ② 6 例上没有出现「当前候选全面优于官方」的证据：T1 平手 2/2，T2 候选 1/2 对官方 0/2，T3 事件全对而官方时间误差更小（10.5 对 28.6 月）。 ③ 这 6 例不足以支撑任何性能结论：T1 标签是伪标签、采样温度 0.3 单次运行方差极大（同一例两次跑，官方 T2-001 从对变错）。本轮定性为内部基线校准，不是泛化证据。

5. 冻结与补丁台账

A 臂（官方原件）

  • 来源 DIAGNijmegen/chimera-agent-baseline commit 1afa788（2026-08-10），落盘 ~/CHIMERA-armA，21 个模块，指纹 output/bench/freeze_CHIMERA-armA.json。
  • 补丁仅 2 处、共 32 行：① models/openai_compat.py 在拿到响应后追加一行 usage 记录；② run.py 给 MCP 子进程转发 PYTHONPATH 等白名单变量。补丁文件 official_compat.patch。
  • 为什么第 ② 条非改不可：MCP SDK 的 stdio 只透传基础环境变量，丢掉 PYTHONPATH 后子进程会去 import pip 安装的那一份包（指向当前仓库）。第一次 A 臂运行就是这样被污染的——agent 主进程跑官方代码，工具与 RAG 子进程跑当前仓库代码，日志里冒出了只有当前仓库才有的 428 条 QA 与 reranker 加载。该次结果已作废，修复后工具数从 7 回到官方的 6，RAG 日志也回到官方形态。这条也说明：「代码身份一致」必须用日志特征验证，不能假设。

C 臂（Adaptive v2 候选）

  • 当前工作区未提交状态整体复制到 ~/CHIMERA-armC（82 个模块），原工作区未改动。指纹 output/bench/freeze_CHIMERA-armC.json。
  • 按裁定关闭：predictor、reflection、few-shot、B/C 未成熟机制、CHIMERA_WEIGHT_TABLE=0。reasoning_align 在 adaptive 路径下本就以 align=not adaptive 关闭，无需额外改动。
  • 新增一段入口代码 benchmark_entry.py（约 230 行）：把「三份命名合成夹具」换成「一份预先登记的真实病例清单」，逐文件 SHA 绑定、私有空输出目录、逐例 12 次请求 / 195,072 token 预算、原生 /v1/chat/completions/input_tokens 计数。Adaptive 控制器、信息准入台账、审计日志一行未放松。
  • 准入链上另需放行两处：entry_profile.verify_identity 增加 benchmark 作用域分支；models.load_model 允许 benchmark 作用域加载真实模型（与 host smoke / case pilot 同级）。
