# Git 归档与 Chat 讨论同步方案

状态：方案已准备，尚未配置上传目标或启用自动推送。2026-11-14。

## 已核实

- 服务器项目是本地 Git 仓库，当前分支 master，没有配置 remote。
- GitHub 连接可访问 lancheq/chimera-agent-cloud，当前为公开仓库；不是可默认上传全部研究材料的私有目标。
- 现有 ghsync/git_auto 主要用于下载与本机中转，不能据其名称认定已实现提交／推送。
- 原始数据、模型与 output 已有忽略规则；忽略规则并不能代替对文档、历史跟踪文件和提交内容的检查。

## 触发单位

每完成一个可复核的工作步骤（实现与必要测试完成、批次结束分析或形成明确的失败诊断），生成一次检查点。不是每次保存文件都提交；运行中不封存半写入结果，不因测试失败抹掉失败记录。

## 每个检查点应包含

1. 本阶段必要代码、配置和测试；明确哪些只是试验模式，不能默默改变生产默认。
2. `discussion/CURRENT.md`：最新状态、已知问题、结果含义与下一步，供 Chat 优先读取。
3. `discussion/ROADMAP.md`：优先顺序和阶段门槛。
4. `discussion/EXPERIMENT_INDEX.md`：实验编号、比较对象、固定项、数据接触情况、结果与限制，链接报告。
5. `discussion/checkpoints/<时间-步骤>/SUMMARY.md` 与 manifest：阶段、改动、验收、失败／未知项、代码和资源指纹、服务器原始证据位置。manifest 不嵌入自己所属提交的哈希；提交创建后在独立本地回执记录 commit，避免自引用。

代码与讨论文档在同一提交中对应。Git 历史保存每个检查点；重要阶段可另打不可移动的存档标签。恢复旧版本不覆盖当前未提交修改。

## 上传边界

允许清单经检查后包含必要源码／配置／测试和适合共享的汇总文档。原始患者记录、逐例临床解释、GT、含病历的 trace／审计台账、模型权重、向量资源、凭证和环境密钥不上传。私有仓库也不默认接收这些文件。

原始证据在服务器只读保留，上传汇总指标、指纹与相对定位。已有 reports 不能整目录无检查推送；可能引用病例原文或本机个人材料。发布前检查 staged diff、文件类型／大小、凭证及患者内容，并留审核回执。禁止 git add . 后直接推送。

## 推送与确认

目标仓库／分支确认后，在 codex/ 前缀分支准备首个完整候选与文件清单；不强推，不覆盖云端已有历史或默认分支。用显式文件清单形成提交，再推送并核对远端分支 SHA。网络或权限失败保留本地提交和 pending 回执，明确标未上传，不误报同步完成。

自动同步应接在执行会话的阶段结束流程，而非依赖本讨论会话常驻。实施前先核对执行会话是否正在写同一文件；本方案不修改其执行代码。

## Chat 阅读约定

Chat 通过其已连接且有权限的 GitHub 工具读取仓库，先打开 discussion/CURRENT.md 与 EXPERIMENT_INDEX.md，再按问题追踪代码和报告。每次讨论先注明实际读到的分支／提交，避免把旧索引当最新状态。不能保证推送后立即自动刷新所有对话；必要时提供提交链接或对应汇总文件。

待确认项：使用公开仓库上的经审查讨论资料，还是新建／指定私有仓库统一保存代码与汇总。未确认前不向公开仓库发布。
