## 下一项唯一优先工作：既有证据的适用性审查

范围先限于已发现的两份任务化规则摘要，以及六例中查询／返回／判断的对应关系。只读，不开新生成：

1. 将两份摘要的全部决策条目与原始指南逐条对照，记录文档与版本、原文位置、来源等级、适用人群、完整条件、例外和未核实部分。不能只检查恰好解释某例对错的条目。
2. 核对指南query中的患者事实：已合法观察、共同初始信息、明确待证假设、无依据断言分别登记。固定query与观察不一致不等于需要更复杂规划器；可能只需一个事实约束。
3. 明确T1判断的是本次活检动作，区分初始、重复、监测中的确认性与治疗前其他场景；识别参考管理意图是否在输入中有足够支撑。不按GT选一侧数值、不把参考文字补到初始Prompt。
4. 对相同临床内容的两份诊断请求列出非临床差异（观察顺序、预算拒绝、预算文本、query与指南段落）。先定义哪些是必要事实、哪些是运行说明；不在这个步骤重写运行上下文或重判标签。

交付为可复核的来源／适用条件台账、明确的待核验项和一份单一候选建议。冻结旧KB与全部实验；若后续确需资源修订，另建版本和来源指纹。此阶段不同时改重排器、检索粒度、诊断提示、停止规则或预算。

## Direct ReAct作为基本参照的接口草案

这是对照准备，不是新研究贡献或立即运行授权：

- 使用同35B权重、同来源版本、同工具服务／合法可见边界和信息账本；不使用额外隐藏数据或质量标签。
- 原生观察→工具／停止循环，不强制共享初始计划／首次观察；该差异是完整架构比较的一部分，不混称与当前S4同一项局部消融。
- 共用最终诊断／填表模块。必须先明确最终诊断只接收什么证据、拒绝及控制文本如何处理；若修订证据投影，所有新对照共同采用，不能只给Direct ReAct去噪再与旧结果比。
- 患者信息单位、获准尝试、动作数及停止上限明文登记。按实际模型／工具调用计计算，不把省去planner的调用免费补给其他组，也不以同token掩盖不同患者信息权限。
- 复用现有`workflow: react`只是实现线索，不代表已验证与Shared Plan同边界或可一键公平比较。先验收工具schema、拒绝、停止、恢复、上下文和费用，再冻结候选。

暂不实现多个策略或部署三组实验。

## 何时再跑验证

先完成上面的证据审查，再只选一个可检验机制：根据证据选择query事实约束、来源／适用条件约束或诊断上下文规范化中的一项，不能同时全加。选择标准须先于新的正确率观察。

在下一正式比较前确认数据来源、患者分组／历史接触、可用独立验证和参考含义；如仍只有已暴露91例，明确其只是探索性内部证据，不通过反复提示或阈值选择声称泛化。沿用原源数据，不按GT裁剪冲突病例。

要验证“补哪条信息会改对”，需受控证据干预；“相同请求不同输出”需固定请求的重复证据。现有复盘两者均没有，不能把观察性案卷当成这些实验已经完成。新临床生成须另行登记有限任务与主要指标，再按授权执行。
