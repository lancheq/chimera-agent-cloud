## 研究主线和当前位置

主问题是：**同样的初始患者信息、工具权限和成本约束下，允许 agent 根据新证据调整取证与停止，能否获得更好的诊断／成本权衡？**

当前 `planned_react` 已包含 `agent ↔ tools` 循环，并非只能按单向固定步骤执行；固定的是部分外围节点、强制规则和输出处理。已经有自主取证入口和架构筛查，尚未完成公平的自主决策优势验证。S2及S3成品现已按范围验收，P7冻结协议已交付；下一步是审阅后部署一次有限的S4内部配对验证。先不继续 predictor 融合、扩维或节点策略训练。LLM 某一阶段的准确率改善单独计为正向结果；下游处理另列。

推进方式固定为：文献与现有实现核查 → 完整候选与工程验收 → 有限开发筛查 → 冻结设计的配对验证 → 分析决定是否进入下一机制。前一机制未形成结论，不并行铺开多个研究方向。完整候选指接口、失败处理、记录与评估齐全，不要求把所有未来功能一次做完。

## S1：数据清理的可执行边界

本轮输入审计见 [前置审计](../reports/ROUND2_PREREQUISITE_AUDIT_20261113.md)。三个来源共 1,275 条记录，绝非已证实 1,275 位患者。两份 release 各 423 条，任务／ID 键全部重合，419 条非空 embedding 指纹一致，但 prompt 和 clinical 指纹均不同：必须保留版本并核对患者关系，不能当独立扩容，也不能按 ID 直接覆盖。标签仅检测文件存在，没有读取。

冲突处理分两条账：

1. **输入盲审与评测清理**：不看 GT，按同一患者、就诊时间、测量单位、原始报告、是否修订版建立证据表。不同日期的 PSA 首先视为纵向记录；“提到活检”不代表本次已经活检。无法裁定则保留两来源和不确定性，或预先定义隔离子集，不按模型是否答对删病例。
2. **GT 辅助错误诊断集**：可看答案研究“标签为何如此”，可用于训练标签复核和设计假设。它必须标为已接触、诊断性材料。不能依 GT=yes 就删掉支持 no 的输入，再把这批整理数据当独立验证。独立临床裁定或主办方更正可以形成新版本，需保留原版、改动理由和盲审记录。

旧审计 61/197 例存在候选冲突，但有 GT 的 28 条冲突全部未在参考自由文本命中任一侧数字，不能声称已证实“医生明确选了一边”。本轮 Phase 2 的 36/195 是启发式候选数；缺少旧卡片字段会降低检测机会，不能称冲突率已经下降。

## S2：成本不是 prompt 中一句“少做检查”

先区分三类量：

- **官方工具使用分**：本地冻结官方 evaluator 对已揭示资料栏去重，计算 `|agent 与医生共同打开的栏| / |agent 打开的栏|`。多开的栏被等权惩罚，漏开不罚，不开工具时该分为 1。这不是人民币／美元费用，也不是运行时预算。
- **信息获取成本**：当前工具主要返回预存病历栏，不能自动解释为真实新做 MRI／穿刺。新检查的货币、等待和风险成本需要另外有来源的模拟定义；没有价格表时不编造真实费用。可先用明确标注的单位揭示成本作为研究代理，单列其局限。
- **计算成本**：模型次数、输入输出 token、延迟和显存。与信息获取成本分别统计。指南检索也可经 MCP 传输，MCP 是工具接口；低成本指南与高代价新增患者信息的比较取决于动作本身。

实现要求：通过官方 MCP 界面调用；权限／账本放在执行前的共同边界，不能只靠模型自觉，也不能用替代接口绕开官方约束。每条事件至少含病例、动作、目的、请求字段、允许状态、成功状态、实际返回来源、费用类别、预算前后、缓存／重试、时间。并发请求先原子预留预算；失败尝试成本与成功揭示成本分账；同一资料重复访问不重复计算新增揭示，但仍记录计算开销。读取别的病例必须失败。

初始已给出的信息不重复收取揭示成本；经明确授权打开的资料才能进入 LLM、few-shot 查询、predictor 与影像分支。服务端保存原始文件本身不是泄漏，绕过合法可见集合使用文件里的信息才是缺口。

已发现需处理的路径：planner 的索引按当前 case_id 回填缺失查询特征；T3 默认关闭 cost_align；影像向量的来源／授权需核对。其存在尚不代表每次实验都走了该路径，逐例实际影响需事件证明。当前回合不改变生产决策。

## S3–S4：保留 plan，比较“能否根据观察改计划”

文献中 ReAct 会交错推理与行动，计划可在循环中更新；ReWOO 则专门将规划与观察解耦。因此规划是一种能力，独立的 planner 节点是一种实现选择。[ReAct](https://arxiv.org/abs/2210.03629)、[ReWOO](https://arxiv.org/abs/2305.18323)。

旧四组比较还改变 planner 专用示例、预执行工具和指南动作空间，只能筛查实现差异。下一次核心对照不直接删除所有规划：

- 两组相同初始可见信息、规划生成器／示例、LLM 与参数、工具权限、检索版本、最大预算和共同输出模块。
- 固定组执行预定的取证计划，按冻结规则结束；自主组在收到结果后可以重排／替换后续取证、查询指南或提前结束。初始计划应复用同份生成产物，避免初始规划随机差异混入。
- 主分析看无 predictor 参考提示与覆盖的 LLM 核验后决策；已有生产管线作为单列参考。共同后处理的结果只作独立次要分析，不决定是否承认 LLM 阶段的正向进展。
- 单列诊断正确率／任务指标、官方工具分、信息获取代理成本和计算成本，画准确率—成本权衡。不用“零工具得高工具分”代替正确诊断；如需非劣效界值或预算水平，只在开发集冻结，不能看验证结果后补定。
- 开发筛查先用少量代表性病例检查轨迹；正式批次使用同病例配对、患者组隔离、固定种子和缺失处理。重复种子不增加患者数；择优方案后再到未参与选择的评测池确认。样本不足则给区间与限定结论，不硬说显著优越。

这是依据文献提出的本项目对照设计，不是声称论文已经证明该方案在 CHIMERA 更好。涉及指南时两组都使用同一检索器；自主组改变“何时／是否查”，检索器质量留到 S6 单独验证。

## S6：怎样拆开评估 RAG（先保留框架，尚不部署）

RAGChecker 将检索召回与生成器对上下文的利用／噪声敏感性分别诊断；ALCE 另区分回答正确性与引用质量。这里采用分层思路，但临床条件适用性需要另外人工标注，不能照搬自动指标即称临床可靠。[RAGChecker](https://arxiv.org/abs/2408.08067)、[ALCE](https://arxiv.org/abs/2305.14627)。

| 层 | 固定什么 | 替换什么 | 回答什么 |
|---|---|---|---|
| 检索 | 同查询、语料版本、人工相关性／适用性标注、输出预算 | 召回／重排／规则单元中的一个 | 找没找到适用且完整的依据？查准率、召回／排名、条件与例外完整性、延迟 |
| 证据到诊断 | 同一患者已合法取得的信息、冻结查询、LLM／提示／参数、证据预算 | 检索返回的证据集合 | 证据是否送达、支持了哪些声明、是否改善决策？无检索和专家证据可作为诊断性参照 |
| 整体 agent | 同一工具集合、权限、成本账本、预算、后处理 | 只换一个 RAG 候选 | 经真实路径变化后，诊断与成本是否一起改善？轨迹改变是整体效应，不等同某句证据的作用 |

要定位一句／一段的作用，再在固定上游轨迹和相同患者事实下替换或移除该段并真实生成；结论局限于该受控情境。引用出现、变量权重增加、工具被调用均不能独立证明该段造成正确改判。冻结查询是比较候选时固定查询，不等于所有病例使用同一个查询。

## predictor 与“训练”的说明

历史 T1/T2 训练脚本比较 LR、MLP、HistGB、RF 四类模型；是模型族选择，并非每次诊断都同时运行四模型投票。近期按可见证据重拟合的是小型 predictor，另有离线融合模型，未训练当前 LLM 权重，也未训练 agent 取证策略。当前覆盖规则依任务与开关而异，不是运行时自动发现“大幅超越”才覆盖。

小数据／低维／正则化可以有助于控制方差，模型选择仍需患者隔离评估。更多输入维度留到后置研究，必须记录合法来源和缺失状态。当前 35B GGUF／llama.cpp 是推理部署，不是现成精调管线；量化模型一般并非绝对不能适配训练，例如 QLoRA 使用冻结量化基座与可训练适配器，但不因此在本轮启动训练或换全精度模型。[QLoRA](https://arxiv.org/abs/2305.14314)。

## 每批固定汇报格式

1. 运行准备：资源／接口／权限／预算是否执行，不能用软件通过数称医学准确率。
2. 初步筛查：历史病例上的探索结果；列唯一改变、比较对象和阶段指标。
3. 提分验证：冻结设计后的完整配对结果；LLM 判断、审核、决策处理分别列。正向、持平、负向均写明分母和绝对差值，不用总结果掩盖阶段增益。
4. 下一步：对已完成决定性批次先分析。报告实际是否训练、是否新生成、是否新增独立患者。没有后台任务就明确无需等待。
