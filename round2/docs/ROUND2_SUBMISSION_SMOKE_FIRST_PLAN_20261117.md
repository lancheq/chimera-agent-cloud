# 运行顺序调整：先确认机制与提交链，再用一次验证机会冒烟

2026-11-17，按用户最新要求：“具体调优可以稍微往后延期，先确认新加的机制能够正常触发并运行……构建完成之后先上交用一次验证集机会进行冒烟测试”。此顺序替代先做广泛覆盖／准确率优化再考虑提交的安排。旧计划、C02冻结目录和结果保留。

## 当前决策

下一优先目标改为 **机制触发核查 → 实际提交构建 → 少量离线入口冒烟 → 平台一次验证提交冒烟**。不等待所有医学争议、全库标注或各方向调优完成。C02医学NO_GO仍表示尚无医学效果／泛化证据，不自动禁止做好最低工程验收后、按用户意图的一次平台验证冒烟；不得将这次提交包装为机制医学优越性验证。

本轮只调整规划和生成下一执行任务卡，没有开新会话、发送指令、构建镜像、调用临床模型或消耗提交额度。原C02 Goal保持已完成，不擅自延长为无限自动部署。后续开启／派发执行会话仍先与用户确认；统一sol High。

## 本轮实际核对的缺口

1. `inference.py::_load_config`加载`/opt/app/configs/config.yaml`，当前information_access.enabled=false；C02新配置不会自动合并。C02默认关闭是既定行为，代码已存在不能证明提交路径会触发。
2. `configs/round2_evidence_package_candidate.yaml`的overlay路径仍是服务器`output/.../frozen/resources/overlay.json`；Docker上下文排除了output。必须把候选资源整理到独立提交资产并转换到容器内固定路径，重新绑定指纹；不能把宿主机绝对路径写进提交物。
3. 当前Dockerfile入口直接执行inference.py，模型配置指向localhost服务；该文件没有启动已配置35B服务的步骤。历史container overlay的注释不是现行启动证据。必须核对真正可用的构建recipe、启动脚本、模型挂载和断网运行链，不凭旧镜像标签宣称新版本可用。
4. 本服务器当前没有docker命令／已知容器构建运行环境。历史宿主机6例入口smoke及本次C02 stub集成都不是实际离线容器验收；构建宿主、空间与下载量须先落实。
5. C02仅支持T1、两个核验原文载体和限定格式；T2/T3、Shared Plan研究runner、Reflection、predictor等不能因为打包而默认全开或混用配置。提交到底包含哪些机制，须有明确profile和逐项运行证据。未达触发条件但正确返回unknown／未修改，和机制未接通分开。

以上为本机当前文件核对，不推断未挂载Mac上不存在可用旧构建环境或最新容器。早期GPU、提交次数、镜像配置描述不当作当前规则。

## 新执行顺序与交付

| 阶段 | 有限工作与可验收产物 | 晋级条件 |
|---|---|---|
| P0 提交范围冻结 | 从真实入口列机制、任务、开关、触发条件、消费者和资源；给出一套待审提交profile，清楚列启用／禁用及原因 | 规划确认真实部署的机制组合；不让执行者自行变更研究架构，不能把“全开”当验收 |
| P1 触发与消费核查 | 对拟提交机制准备正向触发、正常不触发、缺条件／拒绝／失败样例；核对调用返回到最终结果的消费链 | 每项状态有代码／事件／产物证据；仅开关为true或输出JSON不算接通；C02全unknown不代替正向样例 |
| P2 提交工程构建 | 独立staging、明确T1/T2/T3 profile、离线资源与依赖、模型启动、非root、实际镜像和模型资产指纹 | 消除宿主路径／外网／旧模块导入依赖，保留旧工作区和冻结实验；确认可用构建宿主及下载／空间成本 |
| P3 本地离线冒烟 | 从真实inference.py和镜像入口检查T1/T2/T3合法输入、模型／MCP、机制事件、超时与decision/reasoning sockets | 同一将上传镜像，断外网、只读输入、可写输出；少量样例按输入规则选择，不读GT，不展开全量提分 |
| P4 平台try-out（若适用） | 核对当前账号／阶段规则和额度后，用同一image/model进行可观察的平台调试 | 不能拿旧“免费／不占配额”描述当现状；本阶段不消耗那一次正式验证提交，其他credit成本先列明 |
| P5 一次验证提交 | 冻结提交清单和镜像/model ID、目标第二轮validation阶段、剩余机会、预期消耗1次、提交后剩余数；只提交一次并保存回执 | 产物及最低工程证据可审查；按用户本次“一次验证机会”的意图安排，不碰test、不自动重试或补交 |
| P6 结果归类 | 分开记录运行失败、接口／输出／评分问题、机制可见性及验证分数 | 先解决阻断；不根据一次隐藏集反馈反复调Prompt、阈值或输入，再决定下一科学实验 |

P3真实模型小冒烟须先登记有限样例、调用上限、占用和估时；任务卡本轮仅准备，不预授权大批GPU运行。若已有明确预算按预算执行；新增成本按用户既定要求说明，不用“冒烟”扩成全量T1/T2/T3。机制未被平台样本触发只能报未观察到，不强迫患者满足合成条件、补隐藏信息或篡改输出。

P5预算仅一次validation，不转作test。用户已表达使用一次验证机会的意愿，不需要反复询问是否愿意用这一次；实际阶段、产物与账号额度尚未核实时，不能现在声称已提交或承诺具体剩余数。若需要具体提交确认，放在可审查镜像／清单完成之后；额外提交、测试集、更多付费credit或新增大规模计算另需授权。失败也按实际平台计数记录，不自动假定退回额度。

## 哪些后移，哪些仍必须保留

后移：真实91例的全面格式／来源覆盖、检索/Prompt/阈值细调、Reflection效果消融、独立泛化与外部数据、RL／predictor扩维。后续不取消这些研究，只先让真实提交链可用。

提交前仍保留：合法信息权限、来源不伪造、未知不补阴性、最低可触发正例／拒绝边界、T1/T2/T3接口、实际离线构建、资源预算与版本指纹。C02格式覆盖有限可以明确带入工程冒烟；它不能被宣称已覆盖真实病历或已改善准确率。
