# 排障行为准则：L0-L3 分层验证纪律（2026-08-27 确立）

> **背景**：2026-08-27 T3 偏置修复后，只跑了 3 case L2 定向验证就准备直接跳到 73 case 全量重跑，被用户拦截。原始 L0-L3 分层规划（见 `完整解决方案路线图_20260826.html` §六 + `诊断前置工作流优化_20260826.html`）明确要求"先轻量排障，没问题再全量"，3 case 通过不等于 50-case 通过（50-case T3 误报率 33% vs 全量 90.7% 的教训证明小样本随机性会掩盖系统性偏置）。

---

## 一、分层验证体系（不可跳级）

| 层级 | 名称 | 规模 | 耗时 | 作用 | 通过标准 |
|------|------|------|------|------|---------|
| **L0** | 静态审计 | 0 case | 秒级 | 代码静态检查（字段/逻辑/配置），0 推理 | 无静态错误 |
| **L1** | 离线审计 | 全量已有 output | 0 推理 | 对已有 output 扫描统计（分布/异常模式） | 无新异常模式 |
| **L2** | 定向构造验证 | 3-5 case | 15-25min | 针对本次修复机制构造定向 case，验证修复是否生效 | 修复机制生效 + 无副作用 |
| **L3 轻量** | 分层抽样排障 | 50 case（T1 20+T2 15+T3 15）或单任务全量子集（如 T3 15-20 case） | 0.5-1.5h（单任务）/ 2.5-4h（全任务） | 排障跑 + 监视器并行，拦截系统性偏置 | 无 HARD 异常 + 偏置方向符合预期 + 分布无漂移 |
| **L3 全量** | 全量跑 | 238 GT（全任务）或 73 case（T3 only） | 6h（全任务）/ 1.5h（T3 only） | 最终指标 + 回归确认 | 指标达标 + 无回归 |

### 关键规则

1. **不可跳级**：L2 通过 ≠ L3 轻量通过 ≠ L3 全量通过。每级有独立的通过标准，必须逐级验证。
2. **L2 是"修复机制验证"**：只证明"修复对这个机制生效"，不证明"修复对全量数据有效"。3 case 定向验证的最小样本。
3. **L3 轻量是"系统性偏置拦截"**：50-case（或单任务 15-20 case）抽样验证，目的是拦截 L2 无法感知的系统性偏置（如分布漂移、基率偏置、样本子集偏置）。
4. **L3 全量是"最终指标确认"**：只有在 L3 轻量通过后才跑，用于产出最终指标 + 回归确认。
5. **监视器并行**：L3 轻量 + L3 全量都必须 `trace_monitor.py --watch` 并行，HARD 异常出现即停主进程修复。
6. **trace_monitor.py 必须存在且有效**：如果脚本不存在，**必须先创建再跑验证**，不允许"用 monitor_progress.sh 替代"就跳过四维健康检查。
