## 目标与依赖

打通已经在 B 线验收中复现的真实 stdio 工具返回分支。合成输入经过正式 `inference.py`、真实 MCP 子进程和原权限账本后，合法的单文本内容应进入既有 SDK 请求和预算校验，随后由合成消费者读到 B 未裁冲突状态，正式入口写出两个结果文件。

以下都是查阅材料。[B 线规划验收](../../round2/reports/ROUND2_B_EVIDENCE_RECONCILIATION_PLANNING_REVIEW_20261118.md)、[B 线执行报告](../../round2/reports/ROUND2_B_EVIDENCE_RECONCILIATION_BUILD_20261118.md)、[G1T SDK 请求边界](../../round2/reports/ROUND2_P01_G1T_SDK_REQUEST_BOUNDARY_20261118.md)。复用上轮入口、合成输入、MCP 子进程和 SDK MockTransport、已验收预算守卫和审计。已知基线是工具成功返回并绑定账本，B 注记已生成，但后续请求因 `Unsupported OpenAI message content` 被拒绝。使用本地当前工作树，先登记 HEAD、任务卡及相关文件指纹，保全未提交修改与冻结基线。

## 执行步骤

1. 沿真实 stdio 返回、LangChain `ToolMessage`、权限回执绑定、G1T SDK 序列化和真实 HTTP body 的既有路径重放一次窄范围合成失败。对照已安装的 SDK、MCP 和适配器接口，记录精确拒绝点及返回结构。查阅既有模式即可。
2. 在一处可靠的转换边界实现最小兼容，首选复用现有文本提取和绑定逻辑。范围仅限来自已核对工具返回的受支持单纯文本块，保留原文本和顺序语义、工具调用 ID、授权关联、预算和原始审计。选择现有端点合同允许的表示。计数器接收的 SDK 有效载荷必须与最终 HTTP JSON 一一对应。若已存在安全可用路径，只补必要接线。保留原始回执与转换后摘要的关联。
3. 保持畸形、混合或多块、非文本、未知字段／来源或伪造成功状态的关闭式行为。禁止扩大数据权限、丢弃未知块后把剩余内容送出、按文本重建授权，或为通过测试放松 SDK 请求合同。已有单字符串路径、错误与预算拒绝语义保持兼容。
4. 在 T1 复测正式入口的真实 stdio 与一次授权工具调用，取得工具回执 → B 未裁冲突 → 后续 SDK 计数 → HTTP 发送 → MockTransport 消费 → 双 Socket 的完整记录。同一条件在 T2 验证共享路径，保留 T3 不借用接口的跳过回归。以无模型、无患者的合成输入测试正向、既有旧形状、非法结构、错绑定、预算拒绝和失败输出语义。选择必要的 B、G1T、工具权限回归，复用原测试命令及资源约束。

## 验收与停止

- T1/T2 的真实 stdio 路径各有完整证据，展示计数、发送与消费绑定，以及两个正式输出的指纹。计数为合成计数器对照，不代表服务器真实模板计数。明确 MCP 接口为真实，患者和模型为合成，最终字段为预设响应。
- 正向测试每例仍仅 1 次合成工具、1 信息单位，比较修复前后请求次数、实际发送状态与载荷；工具失败、超预算和不受支持内容应保留各自原有拒绝或回退语义。默认生产配置、工具权限、冻结结果及 G1R 最终字段合同保持原约定。若正向增加了相对于失败基线的请求，标明这是原来被阻断的后续请求，并和既有单字符串成功对照核对次数。
- 修改限于本问题的工具文本转接、必要的 SDK 或正式入口接点、对应测试与专属产物。用原环境、最多 2 个 CPU 测试 worker。真实模型调用、真实病例或新增临床工具调用、GPU、权重加载、镜像、发布、平台操作均为 0。数据时间资格、迟到原始内容隔离、T3 适配和真实模板计数另待审，属于后续里程碑。
- 触及更宽泛工具返回协议、预算正确性或临床输入权限时，停止对应改动，报告最小可复现证据与解除条件。交付即可停止本轮。共享队列和 Git 由规划会话处理。
