## 停止合同

先沿 `shared_plan.acquire()` 的候选动作、checkpoint、`InformationAccess.execute()` 的权限、缓存、预留、结算和拒绝，到共同诊断逐项核对。用与 Guard 共享的现有权限及成本依据在实际分派前确定费用与合法性。预检在一份可核验的账本视图上判断，不能读隐藏数据、预取内容、发请求、改账或成为真实 admission 的替代。真实工具仍按原事务再验和结算，版本／快照必须匹配。

| 条件 | 授权行为 |
|---|---|
| 本次合法已选动作具备申请/受理余量且成本可支付 | 按原路径尝试。全部已可见的同快照缓存和已核允许的零信息工具在余额为零仍可被原计划选中，照旧计入实际申请/受理上限。知识查询仍须有已验证的快照、合法查询和相应工具；缓存缺字段时按原合同核算缺失部分。 |
| 账本同身份、状态完整且无在途，所选动作本身合法，但新增费用确定超过剩余信息预算 | 发送前结束取证，保存明确的正常预算停止原因、余额和所需单位。该动作不执行、不记为真实受理或成功回执。只用已有获准证据进入共同诊断。保留原策略选择和账本，不能自动重排、换便宜工具或继续试探。 |
| 账本同身份完整且无在途，合法动作前调用上限恰已用尽 | 在发送前用独立的调用预算停止原因封存，缓存和零信息工具均不能绕过。原控制轮、动作上限等正常终止仍按既有合同。仅能从可核验的明确终止状态进入诊断。 |
| 越权、任务／病例／快照错误、无合法查询、在途歧义、工具异常或返回完整性、权限、结算、审计错误 | 延续严格阻断。权限错误优先于预算，不能借余额归零转为正常停止。真实调用中返回的拒绝或突发账本变化不能仅按错误字符串当作成功停止。若出现完整性异常或未结算事务，不发后续诊断、填表，不产生通过回执。 |

正常终止回执至少关联本次运行、预检依据、选中动作、阶段、预算、无在途状态及审计摘要。需与保存的 checkpoint 一致，恢复时防止漏记、重复记账或重放真实工具。审计失败即停。诊断、填表和两路 Socket 沿原路径，未知信息保持未知。不伪造工具响应、诊断或结果，不能用“预检正常结束”代替整个结果验证。

## 零生成验收

1. 保全原 A-F06 失败工件（请求、模型响应、私有 SQLite、控制器审计、源及夹具 SHA），逐段复现同一取证序列。用冻结 F06 的受控正式入口、现有合成响应／真实本地契约代表，复现 3 单位耗尽后选择收费动作。证明原版在拒绝处结束，新版在该请求发出前正常停止，后续到共同诊断、填表和双 Socket，诊断仅保留已验明的原观察。对照动作审批、账本、请求阶段、计数和结果完整性。
2. 最小补充回归覆盖余额为零的同绑定缓存/合法零新增信息、两者达到调用上限仍不得执行、权限错误优先于预算、突发 Guard 拒绝、工具异常或审计失败没有双 Socket。保留 G1T 的 SDK/最终载荷绑定，必要时宣告模型阶段为 MockTransport。运行相关回归，逐项列最早失败与缺证。
3. 修改限于既有 Adaptive 的正式受控路径和必要的 InformationAccess 查询／共用会计核对、相关验收。既有行为尽量复用，无新增临床规则、Prompt 调整、真实端点、GPU、启动权重、新病例、容器、公开上传或平台动作。最多 2 个 CPU worker。若需要改变 Adaptive、Guard、拟批准的停止合同或纳入更多机制，停在已收集证据返回规划。
