1. 以 [T3 规范修复验收](../../round2/reports/ROUND2_A_T3_INPUT_UPLOAD_PLANNING_REVIEW_20261119.md) 和 [A-G2 实际宿主验收](../../round2/reports/ROUND2_A_G2_ADAPTIVE_HOST_SMOKE_PLANNING_REVIEW_20261119.md) 为基线。只使用冻结 F06 原件及当前修复后的受控 Adaptive T3 工程 profile，核对 SHA-256、导入位置、配置、启用和关闭的机制、可信端点及权限。沿用已验收 Guard、冻结 RAG、G1T 及模型表单/Socket 投影。未验收 B/C02、Reflection/atomic、predictor、few-shot、影像取材和覆写保持明确排除。仅可制作本轮隔离运行配置或小型复用 runner 于专属目录，不修改生产源码/默认配置及旧工件，不重新跑三任务或调 Prompt。
2. 优先复用已验身份的本地 35B，无现成服务时，可用已登记原 GGUF/二进制、空闲 1×RTX 3090、可信回环、单 slot、串行恢复一次。先实核资产、PID、显存与内存和模板，沿 A-G2 已验证的 16,384 slot。预计机器峰值参考约 21,700 MiB GPU／21.9 GB 进程 RSS，CPU 最多 8 线程；另一 GPU 不动。最多 8 次无患者非生成预检，另至多 13 次随运行的身份与计数请求。单例最多 12 次真实发送、3 信息单位、6 工具申请/受理、5 控制回合，无隐式 SDK 重试。每次 input + max_output ≤ min(16,256, 已核 slot−128)，合计预留 ≤195,072。控制/计划输出上限 1,024，其他获批阶段 ≤4,096。身份、精确计数或资源不符即停；退出只停止本任务自启 PID。
3. 走根 `inference.py` 正式路径。审查所有 planner、观察后决策、诊断、填表及任何获准后续请求的实际 HTTP 载荷。核对 `months`、结局、参考分和未知扩展没有进入，也未从草稿或旧历史再现。旁证要追到真实工具账本和私有的原件→准入投影→模型视图。逐一回读两路输出，审查是否把推测、未知或未取证的术后随访／复发写成已观察事实。真实发生的非空改订、空计划停止和未触发分列。没有人工重跑找好结果。若发生字段泄漏、输出无依据地宣称已观测随访、请求或输出契约失败，保留失败和最早阶段，阻断病例试跑。
4. 完成单例，即使失败也写报告，保留原试跑历史，不覆盖旧 F06 工件。全量审计在临时目录清理前导出到权限受限目录。
