# C01｜指南正文定位

[公开版省略逐例记录；汇总与机制结论保留。]

研究问题是目录或章节标题占据检索结果位时，可支持当前问题的推荐正文在哪一步丢失。区分原始来源缺正文、正文未进入索引或被切散、候选召回遗漏、排序与截断损失、证据包装未呈现，以及 query 本身的事实或目标偏差。少量已暴露轨迹用于定位，不估计全队列失效率。

## 输入与步骤

1. 绑定 A01 的 6 次检索、48 个返回位置、当时可见事实与 S4 v2-r1 的实际知识快照。复用 A01 的 query 结论以及已核验的来源材料。确认冻结入口实际启用的路径、截断参数与版本，不从工作区最新代码倒推历史排名。
2. 对每次查询，在查看历史排名前定义目标决策场景及候选指南版本、章节或推荐编号。以相同版本的原始指南核对支持段是否包含对应人群、条件、建议和关键例外。区分目录/导航、原文正文完整或不完备、可溯源 QA 和来源未核材料。带标题且同时有推荐正文可以合格。病例条件不足写 `UNKNOWN`，用合法已见事实判定，GT 不参与选题或匹配。已发现影像分级错误的查询单列，按原 query 与意图分别标注，当轮不改写它。
3. 用具名快照的只读导出、现有记录或私有副本核对正文是否已入索引。区分源文件缺失、冻结索引无正文、文本抽取或切分让支持不完整、索引存在以及证据不足。版本不明或未能定位时保留 `UNKNOWN`，不把邻近章节或其他版本的文字当证据。
4. 若现有证据支持，逐查询关联 dense、BM25、RRF、重排输入与输出、最终 chunk 和追加的 QA，最后定位 C02 包装及送入模型的证据。无中间日志时将损失区间标为未知。QA 旁路单独记来源和位置，避免用它与正文重排分数做统一解释。C02 的合成案例只用于核对后置包装边界，历史轨迹如果未运行 C02，应记 `NOT_RUN`。
5. 交覆盖和误命中基线。分母以 6 次查询、48 个返回位置及去重后的正文/目录 ID 分列，并注明适用条件完全核实的条数。主读数为至少命中一条完整可追溯推荐正文的查询数；并列导航占位数、首条正文位置、条件缺失、包装后无可用证据的查询数。最后一项仅在确有包装记录时计数。诊断上下文中出现证据只记送达，可核实的引用或误用另记。
6. 根据归因只提出一个下一步比较。正文缺失或切散就优先审可追溯的正文与切分；正文已入库但落出结果窗，再考虑文献支持的有限检索或重排改动；明确的 query 事实错误移交 A03 的单变量验证。只有历史 stage 证据不足时，才提出最多 6 条原 query 的固定快照 CPU 重放方案。新增机制先比较原始论文与作者实现，之后单独登记固定 query、基线、主要读数和停止条件。

## 交付和验收

只写 `output/planning_C01_retrieval_20261118/` 与 `reports/ROUND2_C01_RETRIEVAL_LOSS_LOCALIZATION_20261118.md`。输出目录交 `handoff.json`、输入版本清单、6 查询逐阶段私有矩阵、48 结果归类或未知说明、聚合基线和一个后继候选。逐条说明证据来源及无法判定的位置。若某查询无法绑定原快照或中间节点，保留该项及理由，公开汇总只列计数和经核验的公开资料版本。

本轮使用已有材料和冻结索引的只读查证。模型生成、检索重放、索引重建、生产配置改动均为 0。禁止从患者 GT 反推推荐正文或把历史 query 原文发往外部服务。完成交付后停在规划审查。C02 真实利用效果和真实诊断对照保留为后续任务。
