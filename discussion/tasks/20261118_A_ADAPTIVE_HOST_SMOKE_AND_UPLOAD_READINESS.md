## 依据与冻结范围

以本地含未提交修改的工作树为实际基线。复用 [A-SMOKE 执行报告](../../round2/reports/ROUND2_A_SMOKE_READINESS_20261118.md)、`output/a_smoke_readiness_20261118/{readiness_matrix.json,g2_proposal.md}`、G1A/G1R/G1T 和 B 工程验收，均为查阅材料。保全旧实验、现有暂存区和无关工作。使用矩阵里的冻结无患者 F01/T1、F05/T2、F06/T3，验收期望文件只给审查，不进入模型、工具或样例目录。调用根 `inference.py`，保留当前平台输入及双输出形状。失败时不生成占位诊断。

宿主专用工程 profile 只验证冻结 S4 v2-r1 的 Adaptive 单例语义：同一初始计划、首次观察后允许替换剩余清单、空计划停止、后续诊断/填表走既有受审入口。T2/T3 是按本任务合同的工程适配，使用本任务工具白名单，不从 T1 研究结果推定临床适用性。使用逐任务可信 profile、Guard、G1T SDK 最终 JSON 的硬预算、已批准工具与来源、持久审计、既有输出契约。每个 profile 逐项登记 D01–D07。有成品发布待裁事项则列为上传阻断。

首批有意使用 S4 已冻结的无 predictor 及无旧 Reflection/atomic 的工程观察范围。无权新增 predictor、few-shot、影像取材、旧决策层、校准、G1R/外部 Reflection 或最终字段覆写的临床权限。B 和 C02 的正式策略仍待裁。沿用当次明确获批的合法知识来源与冻结 RAG。F01 若缺 C02 必需的已授权来源或消费接线，应显式记该门槛未验，严禁静默降级、把跳过计为覆盖或将本 profile 作为提交配置。保留 T3 明确无 B 时间证明时的跳过原因。默认生产配置和未审分支维持原样。

## 第一阶段：修复实际入口与零生成验收

复用现有 S4 的计划/取证核心和已验收的计量、权限、填表、最终 Socket 合同，作最小正式入口接线。禁止运行双臂 runner、复制控制器或宣称旧 `planned_react` 等同 Adaptive。仅允许必要的入口、单例 workflow、可信隔离 profile 与测试接点变更。不得把真实端点接到 synthetic-only profile，不改其拒绝真实模型的合同；如需新增宿主限定 profile，必须绑定代码、配置、环境、运行标志、无患者输入、任务、可信 loopback 端点、实际模型身份、请求上限与独立不公开的审计路径。生产允许表保持冻结，任何未识别输入或身份走拒绝。

优先使用现有合成材料做最小分支验证。正式入口必须记录 Adaptive 身份、计划替换、空清单 STOP、权限/错 profile 拒绝、计量拒绝及两路输出归属。核对 T1/T2/T3 权限和最终字段，禁止添加无关 B 模拟或策略优化。先保存 `gate1.json` 的代码指纹、证据和逐任务通过或失败理由。若不能在不放宽权限、不改变策略、不绕过共享计量的情况下实现，停止，不启动服务。

## 第二阶段：有界真实模型验证

只在第一阶段通过后执行。优先复用已身份核验的本机 35B。需要恢复时仅允许使用 A-SMOKE 中已登记的现存 llama-server 与 GGUF、本机私有回环、一个当时空闲的 RTX 3090、单 slot/单并发。启动前核对资产指纹、模板、设备、可用显存、CPU/RAM/磁盘、版本和端口，无合格空闲资源即停。另一 GPU 或他人进程不可更动。不下载、不训练、不改二进制、不改模板或降低原冻结模型规格。一次启动尝试。记录 PID、进程身份、实测可用 slot、峰值和日志，收尾只停止本卡自启进程，复用实例留由其所有者管理。

先做至多 8 次无患者的非生成模板计数核查，身份、普通请求、工具返回、控制器严格 JSON schema、填表 assistant 前缀均有证据。以实际 G1T SDK 最终 JSON 与活实例原生计数及模板/分词一致为门槛，不能确认模板、输入计数、结构字段支持、服务器身份或硬预算则止于预检。无需靠真实生成去证明已知不支持的协议。

真实模型调用仅用于固定无患者夹具。先 F01/T1。检查其真实取证、诊断与双文件，确认无身份、预算、信息越界、合同、审计或落盘失败；通过才依次 F05/T2、F06/T3 各一例。自然未发生某机制时写“未触发”，保留真实输出并按门槛审查：不得重试换样、调 Prompt 或用 stub 替代。若是既定必需事件缺证，则停止扩大并说明。上限每例 12 次真实发送尝试、3 信息单位、6 工具请求／受理上限、5 个决策轮；总计 36 次、9 信息单位，另有预检后最多 37 次身份/正式计数。SDK 隐式重试 0，每次重试或表单补救都计入。控制/计划最多 1024 输出、诊断/填表最多 4096。精确 `input+max_output` 每次不超过 `min(16256, 已核 slot-128)`，全轮保留上限 585216。发生首个越界或拒绝后不继续下一例。逐例保存 SDK/HTTP 绑定、控制器 trace、工具账本、预算与双 Socket 指纹及真实输出摘要。保留失败、未触发和待人工分析项。无医学性能比较与策略变更。

## 第三阶段：上传准备

三任务工程结果回读合格后，整理候选源码与逐任务 profile、依赖／模型启动／非 root／资源、离线镜像最小清单和发布阻断，继承既有 P01-PACK/GIT 审计。现有 builder 或平台进程式/invoke 合同、GPU 规格未证则标阻断；不安装新环境、不创建正式镜像、不上传、不登录或发起官网作业。Try-out 与 validation 分列，账号具体动作须核实。若消耗首次正式 validation，B 正式验收是硬前置。此轮以便于规划复核的材料为交付，平台操作必须另授权。
