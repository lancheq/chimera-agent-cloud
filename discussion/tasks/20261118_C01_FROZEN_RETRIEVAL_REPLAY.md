## 有限任务

用原样冻结检索链补录中间候选，定位完整推荐正文在哪个阶段退出候选范围。依据 C01 已验收的首轮报告和 `output/planning_C01_retrieval_20261118/` 中的 `input_versions.json`、`query_stages_private.json`、`result_positions_private.json`、`targets_before_rank_private.json` 和 `next_candidate.json`。历史中仅 3/6 次返回完整目标正文，其余 3 次的目标正文在冻结索引中可定位。原日志缺阶段名单，回放结果应和历史直接证据分列。

1. 先绑定 S4 v2-r1 的实际源码、v4 知识快照及语料、向量、QA、编码器、重排器和依赖版本。确认 Python 实际导入冻结源码，并核对部署记录中的检索参数。用冻结资源的私有副本，核对前后指纹。环境不符、资源缺失或任何必需组件回退时停止并交具体缺口。
2. 复用经校验的原始检索实现。旁路记录函数输入输出和实际裁剪，保持原排序、距离、阈值、tie-break 和结果格式。一次 CPU 加载，最多对既有 6 条查询各回放一次，严格使用原 query 字节。已知错误影像分级的查询保留原文，原 Query 与合法意图分别解读。纯本地检索，模型生成、患者取证、GPU、索引重建和生产文件修改均为 0。若需写探针，只写本任务输出目录。
3. 记录 dense 前 20、BM25 前 20、合并候选及 RRF 全序、截断至前 30、重排实际输入和 512-token 对文本的裁剪、重排全序与最终前五。QA 旁路另记候选分数、阈值、最终顺序与追加位置。各阶段绑定记录 ID、位置、分数和内容 SHA。沿用事先登记的完整正文与不完整条目划分，按指南版本与目标场景分别跟踪。
4. 每条查询比对历史最终 5 条正文和 3 条 QA 的完整有序 ID 及文本 SHA，并记录可比评分及差异。精确相符时只报告“固定快照复现中的首次丢失点”，历史未留存的中间秩仍是 `UNKNOWN`。不相符记 `REPLAY_DIVERGENCE`，保留回放所见，避免用该条推定历史丢失位置。对目标没有入索引、未被任一召回通道纳入、合并后被截断、重排后未进返回窗及进入返回窗分别报告。QA 旁路和跨片段不完整证据单列。
5. 交完整 6 条状态矩阵和复现分母。明确有多少历史漏命中的查询复现成功、哪一级丢失有直接回放支持。根据证据最多建议一个后续改动。目录过滤、重排修改、重切分、C02 真实利用对照和 A03 改 Query 均留给后续独立任务。本轮达到上限或遇环境阻断即停，不循环回放追平历史。
